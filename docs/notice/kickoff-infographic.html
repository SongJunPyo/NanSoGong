역할별 처음 할 일

백엔드 · 프론트는 2인 1조 (A조 예원 ↔ 소정, B조 준표 ↔ 민성) · 인프라 경모 · AI 후상
백엔드예원 · 준표
com.nansogong/
├ common/      설정 · 보안 · 예외 처리
├ controller/  URL → service 호출
├ service/     업무 규칙 · 트랜잭션
├ repository/  JPA
├ model/       @Entity (@Getter + 업무 메서드)
├ dto/         record + from()
└ exception/   BusinessException 상속
  1. 표 설계 → Flyway SQL (업무 표에 store_id 필수)
  2. 기능 하나 끝까지: model → repository → … → controller
  3. Swagger · api.http 확인 + 흐름 테스트 1개
클래스명 앞에 도메인 (Inventory…) · 예외는 클래스만 추가
프론트엔드소정 · 민성
frontend/src/
├ api/         client.js request() + 도메인.js
├ components/  ui/ · common/ · 도메인/
├ hooks/       TanStack Query 훅
├ store/       Zustand: 로그인 · 선택 매장
└ utils/       format.js (금액 · 날짜)
  1. 공통 틀 (민성): 하단 탭 홈 · 재고 · 메뉴 · 매출

모두가 지킬 규칙 & 담당

브랜치

내 이름 브랜치 → dev PR. 시작 전 merge origin/dev, rebase · force push 금지

PR 크기 · 머지

기능 하나 = PR 하나. 테스트 통과 + 1명 확인 → merge commit

DB 변경

V<연월일시분>__설명.sql. 머지된 SQL은 고치지 않고 새 파일로

다른 도메인의 코드

남의 표 · repository 대신 그 도메인의 service를 부른다

공용 파일

common/ · client.js · components/ui/ · compose는 고치기 전 단톡 공유

비밀값

API 키는 .env에만. 코드 · yml · 커밋에 넣지 않는다
