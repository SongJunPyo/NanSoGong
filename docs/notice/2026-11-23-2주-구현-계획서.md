### 0-3. 먼저 나와야 하는 것

```
member · store 표 (예원, D2) ─────────▶ 모든 표의 store_id
판매 표 계약 (예원, D2) ─▶ 데모 판매 데이터 (예원 · 경모, D3) ─▶ 매출(5-1) · 추정 재고(3-5) · 운영 제안(6-2)
품목 · 메뉴 표 (준표, D2) ─▶ 레시피 (준표, D4) ─▶ 원가(4-3) · 추정 재고(3-5) · 레시피 AI 추천(4-2)
ai/ 공통 틀 (후상, D2) ─────────────────▶ 모든 AI 기능
승인 공통 표 (준표, D6) ────────────────▶ 발주 승인(3-11) · Tool Calling 실행(6-5) · (3주차) 쿠폰 발행(2-8)
화면 공통 틀 (민성, D2) ────────────────▶ 소정 · 민성의 모든 화면
```

> **판매 데이터는 D2 계약 → 데모 데이터 먼저.** POS 수집(예원, D8 ~ D9)을 기다리지 않도록 D2 에 판매 표 칸을 합의하고 D3 에 데모 판매 데이터를 넣습니다. 매출 · 추정 재고 · 운영 제안은 이 데이터로 먼저 개발합니다.

### 0-4. 표 읽는 법

- 각 표의 열 이름에 담당자를 적었습니다. **그날 그 사람이 할 일**이 칸에 들어 있습니다.
- `—` 는 그날 그 역할이 이 기능에 할 일이 없다는 뜻입니다 (다른 표의 일을 합니다).
- 인프라 · AI 의 전체 일정은 3 · 4장에 따로 있고, 1 · 2장에는 그 기능과 맞물리는 일만 적었습니다.

## 5. 운영 규칙 (2주 동안)

| 규칙 | 내용 |
|---|---|
| 데일리 스크럼 | 매일 10분: 어제 완료 기준 / 오늘 완료 기준 / 막힌 것. 막힌 것은 스크럼 직후 당사자끼리 해결 |
| 조별 API 맞추기 | 백엔드가 API 를 만들기 전에 **요청 · 응답 JSON 예시를 짝(프론트)과 먼저 합의**한다. 프론트는 그 예시로 가짜 데이터를 만들어 먼저 개발한다 |
| PR 마감 | 그날 완료 기준을 채운 PR 은 **18시 전에** 올린다. 리뷰는 다음 날 오전까지 (리뷰어: 백엔드끼리 · 프론트끼리 교차) |
| 완료의 정의 | ① 화면 또는 Swagger 로 동작 확인 ② 흐름 테스트 1개 이상 ③ PR 체크 초록 ④ `dev` 머지. 넷 다 채워야 "완료" |
| 일정이 밀릴 때 | 하루 밀리면 스크럼에서 공유, 이틀 밀리면 그 조의 마지막 날 기능을 [3주차](#7-3주차-이후로-넘기는-것)로 넘긴다 |
| 금요일 데모 | D5 · D10 오후에 15 ~ 30분. 동작하는 것만 보여 준다 (화면 캡처 X) |
| 문서 갱신 | 범위가 바뀌면 이 문서의 해당 행을 같은 PR 에서 고친다 |
